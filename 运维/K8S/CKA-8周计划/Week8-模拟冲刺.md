## 三、考试当天执行策略

### 开考后前 5 分钟（不要马上开始做题）

```
1. 通读所有题目（快速浏览，不做）
2. 给每道题标优先级：
   ⭐ 简单（写 yaml、打标签、改镜像）—— 先做
   ⭐⭐ 中等（RBAC、PVC、Service）—— 接着做
   ⭐⭐⭐ 难（排障、etcd 恢复、NetworkPolicy）—— 最后做
3. 记下每道题的 context 名和 namespace
```

### 时间预算（120 分钟 / 约 17 题）

| 时间段 | 任务 | 累计 |
|--------|------|------|
| 0-5 min | 通读 + 排优先级 | 5 |
| 5-45 min | 简单题全部做完（约 8-9 题） | 45 |
| 45-95 min | 中等题（约 5-6 题） | 95 |
| 95-115 min | 难题（约 3 题） | 115 |
| 115-120 min | 回查标记题 + 验证 | 120 |

> ⚠️ **不要按题号顺序做。** 考题难度是随机分布的，按题号做很容易在第 3 题就卡死。

### 每题标准动作（形成肌肉记忆）

```
1. kubectl config use-context <题目的context>     ← 绝对不能省
2. 读题，划出所有硬性要求：
   · namespace 是哪个？
   · 对象名是什么？（拼错就 0 分）
   · 副本数多少？
   · 镜像/端口/路径是什么？
   · 有没有额外要求（如"不能修改其他资源"）？
3. dry-run 生成模板 → 改 → apply
4. 验证：kubectl get / describe 确认符合要求
5. 检查有没有副作用（如题说"不要影响其他 Pod"）
```

### 卡题处理

```
超过 8 分钟没进展 → 立刻标记，跳到下一题
超过 15 分钟 → 放弃该题（时间换更多题的分）
```

**标记法**：考试界面一般有 flag 功能。没有的话，在草稿纸上记题号。

## 八、附录：模拟考常见「送分题」与「送命题」

### 送分题（务必全拿）

| 题型 | 预估耗时 |
|------|---------|
| 给节点打标签 | 1 min |
| 创建指定名字的 Service | 3 min |
| 扩容 / 缩容 Deployment | 1 min |
| 更新镜像并验证 | 2 min |
| 创建 ConfigMap 并注入 | 3 min |
| 创建 SA 并绑定 Role | 4 min |
| 创建 PVC 并挂载 | 5 min |
| 创建 Static Pod | 3 min |
| Deployment 回滚 | 2 min |

**这些加起来能到 40+ 分。先把它们全部拿到手。**

### 送命题（时间黑洞，先跳过）

| 题型 | 为什么难 |
|------|---------|
| 复杂的多规则 NetworkPolicy | 容易漏方向、漏端口 |
| HA 控制平面搭建 | 步骤多，一步错全错 |
| 集群升级 | 耗时长 |
| 复杂 CIDR 的 ipBlock | 容易算错 |
| 需要改多个资源的连锁排障 | 定位难 |
